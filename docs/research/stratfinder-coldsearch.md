## 1. Goal, acceptance, rules

Build ONE generalized cold search that, given only a capture's placed constraints (the tick-0 X/Z start rect, per-tick boxes, DF corridors as momentum walls, tail walls) and the segment bounds (startTick, landingTick), produces a full input line (key rows, press ticks, one fixed momentum facing, jump-angle turn, air yaws) satisfying every constraint, verified byte-exact through `ExactJumpModel`. The endgame (`docs/VISION.md`) is: two blocks in, full TAS out, optimizing rather than just certifying (it can beat the human line: more margin, fewer input changes).

Standing rules (all user rulings):
- COLD: human keys, yaws, press ticks, debug samples, and the capture's own recorded strat NEVER feed the solver, at any stage. Warm-starting from the answer is cheating. The KNOWN sigs appear only inside validation oracles / MITM validators to check a mechanism, never as solver input.

## 2. The problem structure (why it is the shape it is)

Per tick the state is `s_t = (x_t, z_t, vx_t, vz_t)`. Two controls: a discrete key combo `k_t` (9 options) and a continuous facing `theta_t`. Collision-free X/Z dynamics (`ExactJumpModel`, byte-exact): inertia gate zeroes velocity when `|v|^2 < 9e-6` (per-axis 0.005/0.003 in legacy eras); sprint-jump impulse `+0.2*(-sin,cos)` on fire ticks; input accel `a_t(k_t)*R(theta_t)*m(k_t)`; move then friction `f_t` (0.91 airborne, slip*0.91 grounded). All trig runs through the integer sine LUT: the byte-exact yaw snaps to a discrete lattice, one facing bucket `= 0.005493 deg = (180/pi)/10430.378350470453` (`YAW_BUCKET_DEG`; 65536 buckets over 2*pi). Collisions are never simulated; world geometry enters only as per-tick constraint sets. The model is X/Z + tick only.

The strat class is NO TURN: one fixed facing through the whole momentum, one optional turn on the LAST space press (jump angle, ja), free yaws only in the air after it. Fix the facing and the momentum becomes LINEAR in `(sin theta, cos theta)` and the start position; every constraint box is linear; the only nonconvexity is the single facing angle (discrete, sine-bucket) plus the free air yaws and the discrete per-tick key choice. That is what makes each fixed-facing momentum a small global optimization, not a blind brute-force.

**The load-bearing structural fact** (all four S9 research clusters converged on it): the run-up exit factors as `exit(theta) = R(theta) . S`, where `S = sum_k W_k . a(combo_k)` is a theta-FREE, low-dimensional accumulator (4 reals: velocity-accum `(Fsum,Ssum)` + displacement-accum `(Fdsum,Sdsum)`; each combo's player-frame accel is 2D, the friction weights `W_k` depend only on the tick). theta re-enters only at the run-up->tail seam. Consequences: the exponential run-up is a Minkowski sum / subset-sum over the discrete 9-combo set, not a generic tree; many key sequences map to nearby `S`; dedup keys on the exact 4D `S`; meet-in-the-middle is a 2-SUM on `S`; and bound/reachability pruning of the run-up is provably weak because `evalRange` already encloses `A sin+B cos` EXACTLY via `R sin(theta+phi)`, so where theta is unconstrained (the wide-arc run-up) every sound over-approximation overlaps the target.

Known couplings (all handled): sprint is a state machine (needs W + forward motion; the sprint FACTOR lags `isSprinting` one tick, `factorSprintAt`); ground/air per tick derives from the press schedule except at block edges (the edge-jump mechanic: 1.8.9 resolves the Y collision at the pre-move X/Z, so `onGround` persists one tick past the block edge; jump legality is the tick BEFORE the press within the block hitbox + 0.3 overhang; the press tick may overhang); cycle durations come from ceilings (12 flat, 9 at +1, 3 headhitter).

## 3. Architecture / where what lives

Production (`core/src/main/.../anglesolver/coldsearch/`):
- `ColdProblem` - permitted inputs only: constraints, slip overrides, press ticks (`pressSegTicks` = last ground tick per run), t0 rect, DF corridors as momentum walls, tail walls. `boundsOf` reads bounds verbatim (only EQ gets +-1e-4). `singleHeld` = `lastTied && airAllTied` (the fully-held class). Requires startTick 0.
- `KeyLine` / `LineSpec` - combo alphabet (NONE=0 W=1 WA=2 WD=3 A=4 D=5 S=6 SA=7 SD=8), sprint machine, sig format `<combo><. or +>` per tick, spec building. `FORWARD_SIGN={0,1,1,1,0,0,-1,-1,-1}`, `STRAFE_SIGN={0,0,1,-1,1,-1,0,1,-1}`, `canRun = FORWARD_SIGN>0`. `KeyLine.toRows()` + `LineSpec.build(...).asScenario().toGameFacings(yaws)` (locked-absolute CONTINUOUS game facings, not mod-360) are the input-apply path.
- `ArcSweep` - the incremental per-tick DFS. Carries the feasible facing symbolically as ARCS (yaw intervals) + linear `A*sin+B*cos` forms (`Form` = `s,c,k`; `at(sin,cos)=s*sin+c*cos+k`) for velocity `(vxs,vxc,vzs,vzc)` and displacement `(dxs,dxc,dzs,dzc)`; start rect eliminated pairwise into facing arcs (`leqZero` single-segment form); inertia gate handled by case-splitting on straddle; walls cut arcs with margin `rectSlack+FLOAT_DRIFT_MARGIN(2e-3)`; `funnelOk` reachability (scalar `reachable` ported to arc velocity ranges via `evalRange`); tail-wall margin filter at emission; per-sig arc UNION across gate branches (`emittedBySig`). Modes: exhaustive DFS for level <= `arcExhaustiveMaxLevel(4)`, changes-first order; `setSegments`/`runConstrained` (per-segment alphabet + max-changes, `segChanges`, additive so `segMode`-off paths are byte-identical); `setBudget` (deadline/cancel inside the DFS); `runLevel` root-parallel build (`setRootCombo` per tick-0 combo). MITM primitives: `collectSeam`/`continueFrom`/`tailFeasible`/`backTransfer`(`C_w`)/`mitmTailMargin`/`mitmTailReach*`.
- `ColdSearch` - the byte-exact certify + the ladder. `certifyLine`/`certifySig`/`benchSig` (re-certify a sig to a `ColdResult`); `parallelCertifyFirst` (work-stealing, margin-ordered, top-`JOINT_FALLBACK_TOP(64)` get jointFallback, first-solve wins via CAS); `solveConstrained` (the incremental level ladder with segments); `solve` (the older blind+seeded ladder, reached only by `ColdSearchScreen`); the lattice certify `dualRefineTheta`+`bucketSweepCertify` (LUT-bucket sweep, `BUCKET_SWEEP_RADIUS=40` = +-0.22deg, `BUCKET_SLICE_BUDGET=30`, `BUCKET_LP_MAX=5e-2`); `sliceSolve` entry grid; `heldChainScan` for `singleHeld`.
- `ColdBeamSolver` - the promoted per-cycle beam. `Config` POJO (per-cycle `CycleConfig{fixed,alphabets,glideLo/Hi}`, global `alphabet`+`maxChanges`, `SprintEngage`, caps/threads/budget/`bucketBudget`, `incremental`, `mitm`). `solve(SaveFile,Config,ProgressSink,cancel)->ColdResult` (first-solve), `solveRanked(...)->ColdBeamResult` (collect ALL feasible). Two generators: `cycleFamilies` (the coast/glide/press template, kept for the tuned j154/j716 configs) and `cycleSequences` (the general enumerator). Routes to `solveIncremental` (`solveConstrained`) when `incremental`, and to `ColdMitmSolver` when `mitm`.
- `ColdMitmSolver` - the productionized meet-in-the-middle L2-L3 solver (opt-in `Config.mitm`, default off; byte-identical existing paths; MITM certify is byte-exact so it never returns a wrong solution, only fails to find one). Auto mid-momentum seam `max(firstPress+1,(firstPress+last)/2)`.
- `ColdStratFinder` - the UI backend orchestrator. `Request{List<SegmentConfig> segments; boolean freeYaws; ColdBeamSolver.Config beam}`, `SegmentConfig{int[] alphabet; int maxChanges; boolean ja}` (default alphabet `{NONE,W,WA,WD}`, maxChanges 2). `find(...)` builds a per-cycle config, runs `solveRanked`, collapses feasible lines into `Strat`s (per-segment press-combo groups + held-length window), the real difficulty metric (section 9), and the live `estimate`. `engageTicks={0,1,2}` (sprint cannot engage tick 0 from rest).
- `ColdResult` - the solved artifact (yaws, startX/startZ, `KeyLine`, `path` per-tick X/Y/Z).
- `StratPrefixes` - press-anchored grammar seeds (pessi/fmm/mark/run+jam), consumed by `ArcSweep.runSeeded` and `ColdSearch.solve`'s seeded pass. Superseded in practice (the seeded pass is non-viable, ledger note below) and now caller-less: the older blind+seeded ladder `ColdSearch.solve` and its `ColdSearchScreen` driver were retired in the 2026-08-11 cleanup, so `solve`/`StratPrefixes`/`ArcSweep.runSeeded` remain as superseded production code with no caller. They were left in place rather than deleted to avoid a behavior-affecting production removal during a refactor-only cleanup; a future pass may remove them.

UI note (2026-08-12 rebuild): the cold segment panel is no longer the shipped Strat Finder window. The View > Strat Finder window (`core/.../ColdStratController.java`, `core/.../ui/coldfinder/ColdStratWidget.java`) now runs the warm `StratFinder` catalog (wide `StratPlans` families x strafe patterns x nt/ja shapes plus one-tick shifts), certifies byte-exact, ranks by the ported combinedV4 difficulty (`StratMeasure`/`StratDifficulty`), shows per-edge shift leniency, and annotates rows with corpus provenance (`CorpusIndex` over `resources/strats/library.json`). The cold engines above remain production code reachable from tests and the beam/MITM paths; the cold segment UI panel was retired with the rebuild.

## 5. What is SHIPPED (the wins)

- **The byte-exact certify (the lattice search).** `certifyLine`/`certifySig`/`benchSig` -> `dualRefineTheta` (walk the dual screen into the LP-feasible band) -> `bucketSweepCertify` (enumerate the momentum facing over LUT buckets radius 40, cheap-dual-sorted, byte-exact `sliceSolve` the lowest-dual first) -> the entry grid nails the sliver-thin start. This is the general tool for every "calculated" human line (a no-turn line clearing a constraint by 1e-9 is a lattice point, not a hand-aimed continuous optimum; `ColdLatticeProbeScreen` proved j154's momentum facing has EXACTLY ONE feasible bucket, both +-1 neighbours violate). `heldChainScan` + `ColdProblem.singleHeld` handle the fully-held (no-turn everywhere) class where the closed-form dual degenerates. Certify perf (measured): raw physics 2.4us, `LineSpec.build` 38us, screen ~5ms (~190 sigs/s), certify LAND 105ms (45x from sorting the bucket sweep by dual), certify MISS ~385ms. `ENGINE_FALLBACK=false` (redundant). Data-backed gating: `SLP_RESCUE_TRIGGER=5e-3` (SLP decisive only at ClosedFormSolve viol <= 9.004e-4), `ENTRY_DESCENT_TRIGGER=3e-3` (entry descent decisive=0 across pins); expensive-miss 1664->401ms (4.1x), pins green.
- **Parallel + root-parallel search.** `parallelCertifyFirst` (work-stealing, margin-ordered anytime, top-64 jointFallback, first-solve wins, skips the rank-inverted probe) + `ArcSweep.setBudget` (deadline/cancel in the DFS) + `runLevel` root-parallel arc build (per tick-0 combo, `setRootCombo`, disjoint subtrees, union merge, semantically identical to single-thread). j1150 148s->11s (13x), j925 timeout->104s. The single-threaded quickscreen/probe was the true bottleneck (j925 L2 187s), not the search.
- **The incremental alphabet-restricted level ladder** (`ArcSweep.setSegments`/`runConstrained` + `ColdSearch.solveConstrained`, driven by `ColdBeamSolver.Config.incremental`). Solves long/wide jumps the generate-then-filter beam cannot: j1150 `{NONE,SA,WD,W}` per-seg cap 1 -> L2 byte-exact 49s (was 28.5 min / unsolvable via the beam). KEY: a per-segment cap as a single exhaustive pass is a LARGER space than a tight GLOBAL change budget; drive the alphabet-restricted search with the GLOBAL level ladder (iterative deepening on total changes).
- **The beam cycle-configs** (`ColdBeamSolver.cycleFamilies`, kept for j154/j716/j925 tuned regressions) + the sprint-engage search dimension (`hold(t) = t>=engage && canRun`; let j716 keep sprint OFF at its t18 WD press) + the brake-tick grammar (`coast->glide->brake->press`).
- **The MITM `C_w` join** (`ColdMitmSolver`, opt-in). Cures the naive `|F|x|B|` product's allocation death via `backTransfer` (combo-independent friction coeff `C_w` + per-template `K_w`) + `mitmTailMargin` (thread back walls once per (f,t)). Ceiling L2-L3: j1150 L2 2.5s (filter 535ms, 28439 survivors, 448 certs), j925 L3 7.5s (866 certs / 980k, ordering EXCELLENT).

Standing rule: never a bare "no-go." ### 6a. Cold-search (the search / build wall)

**L1. Objective-bounded B&B (LP lower bound on landing-X).** NO-GO as measured. MECHANISM: landing-X is real-arithmetic, floored by the SHARED landing box (`X>=-1600.137`, below the human optimum -1599.700, so every node LB < any incumbent and prunes nothing) and realized in the free-yaw tail (11 independent air yaws the relaxation aims freely), so LBs are a near-constant across momentum patterns and neither prune nor guide. NUMBERS (`ColdBound`, `ColdBoundProbeScreen`/`ColdBoundWallScreen`): wall-free frac-excluded @half-depth j154 0.344, j716 0.489, j1150 0.707(GO); wall-aware j154 0.300, j716 0.331, j1150 0.512. Human landing X -1599.7000695; every momentum-node LB -1605..-1613. Feasibility box-threading passes 75% (cycle-1 2.58M of 3.43M partials); full 3-cycle cross-product ~12e9, uncompletable. ASSUMPTIONS a future instance MUST weigh: (a) it bounded the OBJECTIVE, not FEASIBILITY (a joint-feasibility LP is untested); (b) the momentum checkpoints were the SAME loose 1.6-block box as start, so pinning start-X barely helped; (c) the 12e9 was the FULL coast/glide/press grid (glideMax 12, ~4701 families), NOT the restricted-alphabet incremental DFS. SUPERSEDED CONCLUSION: the doc concluded "j154 needs a hand-encoded butterfly/neo prior." A later session solved all four cold WITHOUT hand-encoding tech, via a general alphabet shrink + the incremental exact-level ladder + parallel certify. Correct takeaway: the objective bound is too loose and the unrestricted grid too big; a general alphabet shrink suffices, a hand-encoded tech grammar is NOT required. RE-EXAMINE: a feasibility LP; TIGHT per-jump-snapped constraints. (Side note kept: the ~0.03-0.13 form-vs-model divergence is the air-sprint 1-tick lag `factorSprintAt`, NOT the inertia gate; `ArcSweep.stepInto` already lags correctly, so any ArcSweep-fed bound is unaffected.)

**L2. Reachability / affine landing-bound pruning. Tried 3+ ways, all net-negative on the hard jumps.** (i) `funnelOk` tightened to look ahead to ALL remaining boxes: ZERO effect (j154 byte-identical at 37.6M nodes) - "the max-accel envelope IS the tightest SOUND reachability bound and it overlaps the ~1.6-block box regardless." (ii) `canReachTail` (interval landing bound, `TAIL_REACH_PRUNE`): fired ~0% on j716, +16% per-node cost, and even j1150 (~10% fewer nodes) got slower wall-clock. (iii) `axisAccelBound` (alphabet-tightened accel over the arc): 0% on j716 (nodes unchanged 8.25M) and 7-9x per-node cost (j1150 L2 arcMs 10s->95s, so j1150 went 11s->98s); modest node cut only where the arc is narrow (j1150 L1/L2 ~9-15%). SHARED MECHANISM: the hard jumps explode in the WIDE-ARC RUN-UP where the facing is unconstrained, so any sound over-approximation overlaps the target; early in a search almost everything is still feasible (intrinsic to search, not bound quality). CRITICAL ASSUMPTIONS a future instance MUST NOT skip: (a) what was tried was NOT full affine arithmetic - it tightened per-tick accel to the segment alphabet but still summed per-tick `evalRange`s (freeing theta per tick); FULL affine (accumulate the single-momentum-facing theta-form ACROSS ticks, keeping the correlation; max-over-keys is piecewise-convex in (sin,cos)) is UNTRIED and could be materially tighter; (b) the 7-9x slowdown was a naive impl (precomputing per-tick/per-arc accel bounds removes most of it); (c) it DID bite for narrow-arc/tight-wall problems (j1150). THEORY (S9 SAT/reachable + convex clusters): `evalRange` already encloses `A sin+B cos` EXACTLY via `R sin(theta+phi)`, and affine/zonotope only help when the arc is NARROW (post-wall), never in the wide-arc run-up. RE-EXAMINE: TIGHT per-jump-snapped constraints AND only the narrow-arc post-wall region; full affine. Code left behind `TAIL_REACH_PRUNE=false` (removed in the cleanup as proven dead; the design is recoverable from this entry).

**L3. Exact theta-free-state dedup / dominance (`RUNUP_DEDUP`, research idea "the most promising untried no-prior lever").** MEASURED DEAD, 0 hits. Exact transposition table over pre-wall run-up states (key = tick + 8 form bits + sprintPrev + used + segChanges + arc bits; sound for first-solve). j716: L0 states=59, L1=712, L2=2814, ALL distinct, dedupHits=0 at every level. MECHANISM: the run-up state carries the exact DISPLACEMENT forms `(dxs,dxc,dzs,dzc)` (absolute position, needed downstream for wall threading), and distinct combo prefixes reach genuinely distinct displacements (friction weights are distinct per tick, so the weighted Minkowski sums never coincide). Dominance reduces to equality here (future = `S + FutureMinkowski` for both states, so A contains B only if `S_A = S_B`), so richer interval-dominance ALSO cannot fire. SECOND finding: pre-wall states are TINY (2814 of 8.25M nodes at L2) - j716's walls start early (~tick 6), so ~99.97% of the explosion is POST-wall combinatorial branching where states carry arcs + wall-forms and collide even less. So DAG-collapse is dead for the WHOLE search, not just the run-up. RE-EXAMINE: only a genuinely long constraint-free run-up AND legacy per-axis 0.005 inertia that zeros small velocities from rest (real merges); neither holds for the acceptance set. Consequence for MITM: the front/back half-lists get NO collision compression; MITM's win is purely the `b^d -> b^(d/2)` enumeration split.

**L4. Arc-window-seeded certify (`ARC_WINDOW_CERTIFY`).** WASH. Plumbed the emitted feasible arc through and filtered the shared 720-point 0.5deg scan to the arc. j925 L2 certMs 89387->92087 (slightly worse), j154 72051->72955 (no change). MECHANISM: `emit` stores the UNION of feasible arcs per sig (wide, not the knife-edge), so filtering keeps ~all points; AND the certify is not scan-bound (see L6: certify is ClosedFormSolve, not the probe scan). Disabled; the `Candidate[]`/`arcsDeg` plumbing stays (it is also used to seed the certify from the emitted arcs and by two diagnostic screens). RE-EXAMINE: only if per-LEAF arcs (not the merged union) were carried, and only for the minor certify-scan portion.

**L5. The probe / quick-slice screen rank-inversion (j154).** Real. The human line (a real byte-exact solution) probes 0.21 fine / 0.66 coarse while junk probes 0.0 - rank-inverted. MECHANISM: the knife-edge lives in the discrete byte-exact FACING BUCKET; the free-start/probe violation is ~2.7e-2 at BOTH the solve and miss buckets, so no closed-form signal discriminates. ASSUMPTIONS: measured on j154, a d12 KNIFE-EDGE; wider-band jumps probe fine, so "the probe is broken" is not universal. NOW MOOT: the parallel certify skips the probe entirely (certify-all first-solve, margin-ordered). Do NOT resurrect the probe as a gate; do NOT conclude "screening is impossible."

**L6. Path-B "form-intersection replaces the entry grid" - BLOCKED; but the certify HOIST is OPEN.** No closed-form signal discriminates the feasible byte-exact bucket, so the discrete bucket sweep cannot be replaced by a wall-form intersection. STILL OPEN (not a no-go): hoist the translation-invariant `JumpLinearModel`/`FacingPrefold` construction OUT of the per-entry/per-eval loop in `ClosedFormSolve` (identical across entries at a fixed theta; only the constraint TARGETS shift). Certify profile (EXP-4/7): probe:cert = 1:25; certify = ClosedForm 63-65% + probeSolve 30-35% + buildSpec ~0.5%. CORRECTIONS (read the internals before building): (a) NOT cross-survivor batchable - `JumpLinearModel`/`FacingPrefold` depend on the key sequence, every survivor has a distinct sig, so same-theta-different-model gives no reuse; (b) arc-restriction does not help - `bucketSweepCertify` already sweeps only +-0.22deg, tighter than the survivor arc. So the hoist is ~2x at best (the family-doc's 10-100x assumed model-build dominates, unmeasured), risky (shared solver code, 7 pins), entangled with per-theta zeroing (`solveWithPrefold` builds `JumpLinearModel(sc, zeroX, zeroZ)` where zeroX/zeroZ are per-theta). RE-EXAMINE: with a build-vs-solve timer before committing, pins as the gate.

**L7. MITM output-sensitive INDEX (`b^(d/2)` build win).** NON-VIABLE under this problem structure. Per-theta-bucket 1D range index (front points keyed on the tightest-range back wall). j1150 L2: touches=332M = 20x the product (2032%), WORSE than un-indexed (per-bucket replication). Even at 0.8-block walls (shrink x0.5): touches=135M = 16x. MECHANISM: the front points are CLUSTERED in every wall coordinate (`A_w = loX_f + d_seam + C_w*v_seam` barely spreads across front states), so NO wall width discriminates them via a range query; the real selectivity is the JOINT arc (a common startX at some theta across EVERY wall + the tail), which does not decompose into a selective query on any single loose wall - each ~1.6-block wall passes almost everything, only the conjunction prunes. A low-D (or box) index cannot capture a conjunction-of-loose-constraints; polytope stabbing is not reliably output-sensitive and needs tight walls anyway. RE-EXAMINE: nothing available - even tight constraints leave the front points clustered (selectivity is joint, not per-wall).

**L8. Certify-cost hoist is NOT MITM-batchable.** The ~2x hoist (L6) cannot be shared across MITM survivors: the `ClosedFormSolve` model is SIG-dependent, so there is no cross-survivor batch at a fixed theta. The transformative realization (EXP-7): L4 tractability is about certs-to-FIRST-SOLVE (ordering), NOT per-certify cost - j1150 first-solves at 448/28439 and j925 L3 at 866/980k margin-ordered, so at the current 12ms/certify L4 would be tractable IF we could produce and margin-order the survivors. A 2x hoist does not move that needle.

**L9. Constraint-tightening.** PARTIAL lever, not the clean L4 enabler. j1150 L2 shrink x0.5 (1.6->0.8 block): survivors 28439->5371 (5.3x fewer). But the INDEX stays non-selective (L7); and symmetric shrink-to-center DROPPED the known solution (`knownSurv=false`) because the real answer sits OFF-CENTER in the wall, so the 5.3x is an over-estimate. Tight constraints are block-DERIVABLE, not hand-authored: `BlockSolver` derives faces at "obstacle edge +- half-width" (`HALF=0.3`), hitbox-exact; the loose ~1.6-block captures are an AUTHORING ARTIFACT (hand-drawn boxes / rounded values / missing jump-tick constraints). So tightening is a sanctioned, mostly-automatable shrink, but it needs the WORLD GEOMETRY the headless solver lacks (`ColdProblem` only has numeric boxes) - it is a CAPTURE-AUTHORING concern, not a search change, and it does NOT fix the two L4 walls (the filter stays `b^d`, the index stays non-selective).

**L10. Learned global value/policy (DeepCubeA / Levin-PHS / AlphaZero).** SKIP (raise with the user first). The only class that attacks "no LOCAL heuristic" by RANKING run-up prefixes. But a value net trained on solved jumps that include the target's family is a smuggled prior; training on other jumps and generalizing is borderline under the no-prior rule ("if you cannot tell whether a change is a general speedup or a smuggled prior, treat it as a prior").

**L11. Per-theta MILP / CEGIS.** MAYBE (only if everything else stalls). Enumerate theta-buckets; per bucket the momentum is an exact MILP (one-hot combo + linear walls + inertia-gate perspective), LP relaxation prunes buckets. BUT: the run-up is LP-feasible, so CEGIS finds an LP-feasible-but-byte-exact-infeasible sig fast and iterates = millions of them at the knife-edge. Same wall as bound pruning. commons-math3 SimplexSolver is available in core.

**L12. Dual-solver / LP-feasibility prune per node.** NOT tried; predicted to hit L2's wall (run-up states are feasible early) and be even slower (LP per node). RE-EXAMINE only as a SPARSE-node check (segment boundaries / when the arc narrows); it captures constraint COUPLING the interval bound misses, so for TIGHT-landing jumps it could prune where reachability cannot. `ColdBound`'s LP primitive existed to reuse (removed in the cleanup; recover from L1).

**L13. The naive MITM product (`mitmSolve`, `|F|x|B|` continueFrom).** TOO SLOW (j1150 timed out at 8 min): the full product with per-continuation allocation. CURED by the `C_w` range-query join (`backTransfer` + `mitmTailMargin`, no per-pair velocity re-propagation). This is not a dead end, it is the thing the shipped join replaced.

**L14. The gate-free-back assumption (MITM seam choice).** A real soundness constraint, not a bug. The back half is invertible only where velocity stays `> inertiaThreshold` (the zero-snap gate, the classic MITM blocker, lives only in the forward-searched front). XCHECK (`mitmTailMargin` vs exact `continueFrom`+`tailFeasible`): j1150 m=19 clean, j925 m=7 exactOnly=9/90000 (essentially gate-free), j716 m=15 exactOnly=81/90000 (velocity dips below thr mid-back, so the transfer drops ~0.09% of real pairs and is slightly UNSOUND there), j154 m=14 exactOnly=371/90000 (0.4%, worse). CONSEQUENCE: pick a gate-free seam, OR add gate-detection to `backTransfer` (fall back to exact `continueFrom` when the propagated velocity could drop below `thr` over the arc).

## 7. The open problem: L4 (j716 / j154), and the honest ceiling

Both hard targets are BUILD-bound at L3, and their blind (widest-alphabet, no-shrink) siblings sit at change-LEVEL 4+. Measured: j716 L3 build = 211s (431M nodes, complete, NO solution); j154 L3 = 96s (244M nodes, 1.5M emitted / 793k distinct, dist-cap). L4 ~ 2.4B nodes (~20+ min build) + millions of certifies. The two walls: the CERTIFY wall (~3.75-6.2ms/candidate, parallel) and the BUILD wall (arc DFS ~2M nodes/s, root-parallel). No constant-factor speedup (1.5-3x certify or build micro-opt) bridges L3->L4->L5; each level is ~10-30x the last.

The only levers that bridge multiple levels are meet-in-the-middle (`b^d -> b^(d/2)`) or a search-restricting prior. MITM was built, validated, and WINS at L2-L3 (j1150 2.5s, j925 7.5s, byte-exact, ordering EXCELLENT). It does NOT reach L4 under LOOSE constraints, for three compounding, measured reasons (ledger L7-L9, L14): (a) the un-indexed `|F|x|B|` filter is `b^d` (j716 frontCap=2 product 2e11 ~8h; frontCap=1 product 2.34e9 filter 346s -> 7.4M survivors); (b) even with a perfect index the certify floods (survivors = selectivity ~0.1-0.3% * product = millions-to-100M at L4); (c) the index that would bridge (a) is non-selective (front points cluster; selectivity is joint, not per-wall). Every angle now points at the SAME root: the loose ~1.6-block constraints.

**The honest ceiling: MITM = an L2-L3 cold solver under this problem structure. L4 (j716/j154) is OPEN with no identified tractable in-scope path** (`b^d` production + non-indexable joint selectivity are structural). j716/j154 solve fine via (a) the beam's cycle-structured configs (the tuned regressions), or (b) a jump-type-appropriate narrower alphabet (the sanctioned "shrink for hard"). The blind-honesty measurement (fair config `{NONE,W,WA,WD,SA,SD}` maxChanges 2, sprint-engage auto-swept, no per-jump tuning) confirms: cold stratfinding solves the structurally-clear jump (j1150 ~2.5min) but NOT the hard butterfly/knife-edge jumps within budget - which is exactly the LOCKED "general by default, shrink for hard" design, now measured. Note the fair alphabet EXCLUDES pure strafes A/D, and j716's known solution USES A/D, so "j716 needs L4" conflates with "the alphabet cannot contain the answer"; retry with an alphabet that includes the solution's combos before calling it settled. Also confirm level-N "no solution" by certifying ALL level-N candidates with jointFallback (the top-64 recall cap could hide a solution).

The only in-scope L4 ideas left, all unbuilt/speculative: FULL affine arithmetic (L2a, untried); the certify hoist (L6, ~2x, risky); a cheap concrete pre-rank of all `b^d` pairs (rank-all-cheaply + keep top-K, sidestepping the index's non-selectivity, ~30-60x cheaper/pair, validate ordering on j925/j1150 first); the user's chained-L2 / beam-over-hops seeded from MITM front halves (`~k*b^2` not `b^(2k)`; legit cold search if scored by a general objective and seeded from the search's own best partial, never the answer; single-best-greedy stalls in the no-local-heuristic run-up, a BEAM hedges it, which is what `ColdBeamSolver` + the level-ladder + `runSeeded` already do). The genuinely different lever the user has declined for the blind path is a search-restricting grammar prior.

## 10. The constraint-precision lesson (carry forward, do not re-litigate)

Certify viol=0 against the capture's constraints equals "lands in-game" only when the capture's block constraints are precise. `ColdProblem.boundsOf` reads bounds verbatim (only EQ gets +-1e-4), so the coldsearch is faithful; the imprecision was in the CAPTURE DATA. j716's exported sibling fell in-game by 8.7e-8 (X=-699.949999901 vs the real block-support edge -699.9499999880792 = wall +X edge -700.25 + player half-width `(float)0.3`) because its X constraints were mostly rounded `-699.95` (1.2e-8 looser) AND the final jump tick t31 had NO X constraint. After the user re-placed precise hitbox-edge constraints in-game, the found strat solves and is correct (winged-neo tell held: unsprinted t18 WD press + delayed sprint).
