# Design record: node-based solver pipelines (issue #221), M1 + M2

Written 2026-07-12 after the grill-with-docs pass the issue mandated: three verification sweeps over AngleSolverEngine.runJob, the component APIs under anglesolver/solver/, and the UI/save infrastructure, all on branch v1.7.0. This document records the corrected pipeline model, the port contract, the node inventory, and the M1 execution design. Scope decisions from review: M1 only (graph runtime + built-in graphs, hardcoded runJob chain deleted at the end); the M3 editor will use the imgui.extension.imnodes binding already present in the pinned imgui-java 1.86.12.

## 0. Corrections to the issue (grill findings)

1. The issue's single linear stage chain never executes as written. runJob forks on stopOnFeasible/ilsExhaustive: the first-feasible pattern B&B rescue (Fast tier, 3 s) and the seam sweep -> B&B -> ILS exhaustive block (Optimize tier) are mutually exclusive within one run. Fast and Optimize are therefore two genuinely different graphs, which fits the feature.
2. Multi-jump also runs dualChain (keep-better against the receding horizon) and the entire shared tail; setup peel fires only when both horizon and dualChain miss. Spans over 64 ticks (MULTI_JUMP_RACE_MAX_TICKS) set settled and skip everything after warm-up smoothing. The 64-tick cap, reachHeadroom gating, nearMissDefer, and the 2/5 race deadline throttle are absent from the issue.
3. The issue's Candidate is too thin. The real currency is double[] absolute wrapped yaws plus mutations of sc.startPos/startBox/yawLockedPerTick on the mutable JumpPhysicsInputs inside JumpSpec; violation and objective are recomputed on demand, translation-aware via SnapRepairPolish.bestTranslation* when a free start box exists.
4. The issue has no branch-on-problem-property concept. A Router node (predicates on jump count, tick count, free start, near-miss epsilon, reach headroom, legal push, objective cap) is required to express the built-in tiers as graphs.
5. WrapWindowIls operates in game-facing space and on adopt locks all yaws (stageLocked), suppressing translated start and smoothing. In graph form this is topology: the ADOPTED edge goes straight to Emit.
6. Remaining-time arithmetic (remaining/5, remaining*3/4, min(240 s, remaining), relaxation's minimum-3 s gate) cannot exist under per-node budgets; the issue mandates no global timer. Built-in Optimize resolves static fractions of optimizeSeconds at graph build time. Acceptance is verdict-level via the :core:test gate, not timing parity.
7. Dead-code claims verified: solveFromBlocks() has no caller, FreeSpaceDecomposition is dead, the ALM/snap cluster (AlmSnapStage, AlmBfgsCore, SmoothJumpProblem, SnapRepairPolish.run) is test-only. SnapRepairPolish.bestTranslation*/bestTranslationObj are live (engine scoring + WrapWindowIls) and stay.
8. Component APIs are uniform enough to wrap: f(model, spec, feasTol, cancel [, budgetNanos/deadline, seed]) -> double[] | null. Only four config objects exist (SolveCore.Budget, BucketAscentPolish.Config, LongRunSolver.LongRunConfig, WrapWindowIls.Config); every other tunable is a private static final. Promotion of those constants to node params is deferred to M5, one class per commit, defaults byte-identical.
9. Deadline support is partial. SolveCore, IlsPolish, MomentumAssembly, HomotopyCloser, BoundPrunedRecovery, SeamSweepRecovery, WrapWindowIls accept deadlines or budget nanos; ClosedFormSolve, SlpSolve, RelaxationRecovery, LatticeRepair, SmoothingPolish, LongRunSolver accept cancel only and need a watchdog that trips a child token (precedent: the seam-sweep and setup-peel watchdogs).
10. The parity gate is real: ProblemFixture.solve drives engine.solve()/poll(), so ProblemsTest over problems/solve and problems/closedform fully gates replacing runJob. ModernStepRegressionTest is untouched; no model code changes anywhere in M1.

## 1. Port contract

InputRequirement: NONE (self-seeding), ANY, FEASIBLE.
Guarantee (out-branch labels): FOUND, NONE, FEASIBLE, INFEASIBLE, NEAR_MISS, IMPROVED, UNCHANGED, ADOPTED, REJECTED, AT_CAP, TRUE, FALSE, DONE.

An edge A.branch -> B is legal iff the branch guarantee satisfies B.requires. FEASIBLE-requiring nodes accept FEASIBLE, IMPROVED, ADOPTED, AT_CAP, and TRUE branches of routers whose predicate is a feasibility predicate (routers refine the guarantee of what flows through them). The validator computes flow guarantees by fixed point, meet = weakest inbound guarantee, since multiple in-edges are legal.

Graph rules: exactly one Entry and one Emit; an unwired branch falls through to Emit (validator WARN, mirrors the engine's stage-missed-keep-going semantics); every cycle must pass a node with a positive time budget or finite round cap (validator ERROR otherwise); at most one edge per (node, branch); no global timer.

## 2. Candidate and context

Candidate (immutable): yaws (absolute wrapped), violation, objective, feasible, locked, chain label. Start moves are not part of Candidate; MomentumAssembly, FreeStartImprove, TranslatedStart, and WrapIls wrappers mutate ctx.scenario (the solve-private JumpPhysicsInputs copy) on adopt only, exactly as the engine does today.

GraphContext (one per run, worker-thread-owned): spec, scenario, model/exactModel, freeBox, legalGoal, feasTol, the run cancel token, the existing SolveProgress (unchanged semantics: versioned, feasibility-first incumbent, feeds liveBestResult and stopAndUseBest), GraphRunState, sequential flag, cached jump count, lazy dual reach bound. beginNode arms a child token plus the per-run BudgetWatchdog; endNode records the taken branch.

Scoring: the engine helpers moved verbatim: violationOf, exactObjective, scoredViol, scoredObjective, reachHeadroom, objectiveCap, translationDomain, adoptStageResult, adoptWinningTranslation.

## 3. Node inventory (M1, wired components only)

Entry/Emit markers; RouterNode (predicate + epsilon/cap params); DualChainNode (moved engine dualChain: ClosedFormSolve -> SlpSolve -> RelaxationRecovery -> alternate-objective SLP reseeds; keepBetter, relaxMinRemainingSec); RecedingHorizonNode (LongRunSolver; window, commit); SetupPeelNode (moved engine setupPeel; stageSec, candidateMs, stepDeg); CmaesRaceNode (SolveCore.optimize keep-better; restarts, maxEval, polishCount, polishDepth, sigmaDeg, warmStart, budgetSec); MomentumAssemblyNode (start adoption; budgetSec); FreeStartImproveNode (moved engine freeStartImprove; budgetSec, iters); BnbNode (BoundPrunedRecovery; mode FIRST_FEASIBLE or OPTIMIZE with stopAtObjective cap; budgetSec); SeamSweepNode (requires FEASIBLE; budgetSec); IlsPolishNode (requires FEASIBLE; budgetSec, roundCap); WrapIlsNode (gf conversion, translation domain, adopt + yaw lock inside the wrapper; ADOPTED/REJECTED); TranslatedStartNode; SmoothingNode.

RouterPredicate: JUMPS_LE_ONE, TICKS_LE_CAP(cap), HAS_CANDIDATE, CANDIDATE_FEASIBLE_RAW, CANDIDATE_FEASIBLE_SCORED, VIOLATION_AT_MOST(eps), HAS_FREE_START, HAS_REACH_HEADROOM, LEGAL_PUSH, AT_OBJECTIVE_CAP.

Extra control nodes the transcription required beyond the issue's inventory: WrapYawsNode (the multi-jump wrapAll normalization at the old engine line 872 must stay an explicit step to preserve comparison order), ReportNode (the pre-race progress report at line 883), MarkSettledNode plus settled-aware CapCertifyNode (the settled flag suppressing the post-race cap relabel), LabelNode (the first-feasible chain suffix). The chain label and the stageLocked/settled flags live on GraphContext, not on Candidate, because the engine accumulates the label on attempts even while no candidate exists. Known cosmetic drift: the first-feasible label is appended at the race-skip decision point rather than after the rescue stage, so stages appended in between order differently in the label; no test or UI logic reads the label structurally.

Adopt policies live inside the wrappers, byte-for-byte the engine's comparisons: the race adopts feasibility-first on scored violation/objective; sweep, optimize-B&B, and ILS adopt on strictly better objective; momentum and the rescues adopt on success.

## 4. Execution semantics

GraphRunner walks the graph sequentially on the existing angle-solver daemon thread; components keep their internal parallelism (BoundPrunedRecovery pool, SolveCore/IlsPolish parallel streams, sequential flag forwarded). One BudgetWatchdog daemon per run trips the current node's child token at budget expiry and mirrors the parent cancel at a 20 ms poll. advanceNode trips only the current child token; the wrapper keeps the pre-node candidate when the component returns null. Emit publishes the pipeline candidate as-is; it does NOT reconcile against the SolveProgress best, because intermediate reports can predate start-position moves and would be scored against stale ground (Cancel keeps its existing stopAndUseBest semantics via SolveProgress, unchanged). A run that emits no candidate publishes an explicit failure result instead of the legacy silent null. Node-token aborts that surface as runtime exceptions from cancel-only components are contained as the node's fallback branch; genuine crashes still propagate. Safety: unwired branch falls through to Emit; a node executing more than 1024 times aborts the run.

GraphRunState is a versioned synchronized snapshot (active node, breadcrumb, per-node phase/elapsed/budget/evals/branch) polled by the UI like liveBestResult; M4 consumes it for the live canvas.

## 5. Built-in graphs

fast(): single/multi fork, dualChain, horizon + keep-better + peel, 64-tick settled gate, warm-start smoothing, at-cap skip, pre-feasible race skip, race(16/4500/2/FAST), momentum gate on scored feasibility, free-start improve, first-feasible B&B rescue (3 s), translated start, final smoothing, Emit.

optimize(T): same seed skeleton without the pre-feasible skip; race throttled to 2T/5 when exhaustive is pending (multi-jump or reach headroom); nearMissDefer router (violation <= 5e-2 skips momentum); exhaustive block seam sweep -> B&B(OPTIMIZE, stop at cap) -> ILS with static fractions of T; near-miss B&B (<= 5e-2, min(60, T/2)); wrap ILS gated on violation <= 1e-2 or legal push, ADOPTED -> Emit (replaces stageLocked); otherwise translated start -> smoothing -> Emit.

fromBudget(SolveBudget, stopOnFeasible, timeBudgetSeconds): the M1 Custom bridge generating the same skeleton from the existing knobs. Zero save-format changes in M1; legacy Custom saves behave identically.

## 6. M2 handoff (presets), concrete design settled during M1

- GraphPresetFile (Gson 2.2.4-subset POJO, public fields): int version with its own FORMAT_VERSION = 1 and a hard reject on mismatch like SaveIO; name, description, createdAt, modVersion; List of Node {id, type, label, x, y, List of Param {key, num, str, flag}}; List of Edge {from, branch, to}. Param serialization by ParamSpec kind: INT and DOUBLE into num, BOOL into flag, ENUM and STRING into str.
- GraphPresetIO: toJson, parse returning a result with an error message, materialize(file) -> SolverGraph, fromGraph(graph) -> file. Materialize resolves node types via NodeCatalog.byId and branches via Guarantee.valueOf; an unknown type or branch is an error naming the offending node id. Params are applied through ParamValues.set so ParamSpec clamps hold for hand-edited files. NodeCatalog type ids, param keys, and Guarantee names become a stable serialization contract from M2 on; renaming any of them needs a preset version bump.
- FileSystemSaveStore: write/read/browse/moveToRecycleBin are already generic string-blob operations, but list() and parseInfo() are hardcoded to SaveFile. Add an InfoParser hook (small interface plus a constructor overload; the existing constructor delegates to the current SaveIO.parseSafe behavior) so a second store instance can point at parkourcalculator/graphs/ under the game dir.
- Application.setupUi builds the graph store next to the save store and hands it to the solver window (and the M3 editor later).
- AngleSolverState gains graphPresetName (persisted) and a transient SolverGraph customGraph. Effort.CUSTOM keeps its constant name for save compatibility; its UI meaning becomes "user graph".
- SaveFile.AngleSolver gains a nullable String graphPreset (additive, main FORMAT_VERSION stays 1; absent means default). SaveIO writes it; on load, a preset present in the store is selected, and a missing preset, or an absent field with effort CUSTOM, falls back to BuiltinGraphs.fromBudget over the saved customBudget knobs as an in-memory legacy graph. customBudget keeps being written and read.
- GraphFactory.forState CUSTOM resolves state.customGraph instead of calling fromBudget directly.
- AngleSolverWindow.renderCustomBudget is replaced by the preset section: combo over the store's presets, Save As, Reload, Duplicate, and an Open Editor button disabled until M3.
- GraphNode.x and y already exist; persist them in M2 so M3 canvas layouts survive round trips.
- Tests: GraphPresetIOTest (round-trip equality, version reject, unknown-type error names the node id, clamping of out-of-range params), LegacyCustomMappingTest (knob combinations produce the same graph shape as fromBudget), one ProblemsTest-style spot check that a saved-then-reloaded Fast duplicate still solves a known capture, and retarget any existing budget-plumbing assertions (CustomBudgetTest, BudgetResolutionTest) at the fromBudget graph structure where they asserted knob wiring.

## 6b. M2 as shipped (2026-07-12)

Implemented exactly per section 6, with these concrete decisions worth knowing for M3:

- GraphPresetFile and GraphPresetIO live in `core/.../anglesolver/graph/`. The Node POJO's `label` is written from NodeType.label for hand-edit readability and ignored on materialize (M3 may adopt it for user labels). fromGraph writes every ParamSpec with its effective value, not only overrides, so files are self-describing and round-trip equality is byte-for-byte on the JSON.
- materialize errors: unknown type and unknown param name the node id; an unknown branch names the edge's from id; duplicate node ids are rejected. After construction the graph runs GraphValidator and any ERROR (missing Entry/Emit, unguarded cycle, FEASIBLE-requires violation, double-wired branch) rejects the preset with the first issue's message; WARNs (unwired branch, unreachable node) pass. An invalid ENUM value falls back to the spec default via ParamValues.set rather than erroring, matching the clamp philosophy for numbers.
- FileSystemSaveStore.InfoParser is `parse(name, lastModifiedMs, contents) -> SaveInfo`; the original constructor delegates to the old SaveIO.parseSafe behavior, and the graphs store uses a trivial name/mtime parser.
- The graphs store lives at `<saveDir>/graphs/` (saveDir is `<gameDir>/parkourcalculator` on all three loaders). Application.setupUi builds it, hands it to SaveController (preset resolution on load) and AngleSolverWindow.
- Load resolution: SaveIO.applyAngleSolverTo only sets graphPresetName (SaveIO stays store-blind); SaveController.load and restoreInitialTrajectory then materialize via GraphPresetIO.loadGraph when the name exists in the store. A missing or unparsable preset leaves customGraph null, and GraphFactory.forState CUSTOM falls back to GraphFactory.legacyCustom (the extracted fromBudget mapping, shared with the UI's Save As bootstrap). The dangling name is kept so it round-trips back into the save; the combo shows it as "name (missing)".
- Preset UI: the combo's first entry is "Legacy budget" (graphPresetName null, customGraph null). Save As serializes the currently resolved graph (selected preset, or the legacy fromBudget graph built from the saved knobs) under a typed name; Duplicate does the same under an auto "-copy" name; Reload re-lists the store and re-materializes the selection; Open editor is a disabled button until M3. The legacy knob sliders are gone from the UI; the knobs themselves stay in state and the save format and still shape the legacy graph.
- Tests: GraphPresetIOTest, LegacyCustomMappingTest (knob combos match fromBudget shape via serialized-JSON equality, plus knob-to-node-param spot checks), GraphPresetSolveTest (store round-tripped Fast duplicate solves j001 cold under CUSTOM), and graphPreset round-trip cases in CustomBudgetTest. BudgetResolutionTest kept as-is: budgetFor/deadlineNanosFor and friends are still live (Job details and GraphContext), so its assertions still cover real wiring.

## 6c. M3 handoff (imnodes editor), verified facts and integration points

Written at M2 close so the M3 session does not re-derive the ground. Everything below was checked against the tree and the dependency jars on 2026-07-12.

- Binding surface: imgui-java-binding 1.86.12 ships `imgui.extension.imnodes` (verified in the cached jar). `ImNodes` has a global `createContext()`/`destroyContext()` pair plus per-editor `editorContextCreate()/editorContextFree()/editorContextSet(ctx)`, `beginNodeEditor/endNodeEditor`, `beginNode(int)`, `beginInputAttribute/beginOutputAttribute(int[, shape])`, `link(id, startPin, endPin)`, hover/selection queries, minimap, and push/pop color and style vars. The jar also ships `extension.nodeditor`; the review decision is imnodes, do not drift. Core already compiles against the binding (compileOnly), so the editor window itself lives in core/ui like every other overlay; only context creation and natives are loader concerns.
- imnodes addresses nodes, pins, and links by int id; GraphNode.id is a String. The editor needs a session-local int mapping (for example node index, pin = nodeIndex * K + branch ordinal, input pin distinct from output pins). Nothing in the preset format changes for this.
- Context lifecycle wiring points (the two bootstraps): Fabric `loader-fabric-1.21.10/.../imgui/ImGuiImpl.create()` calls `ImGui.createContext()` then `ImPlot.createContext()` (the existing extension-context precedent) and `dispose()` tears both down; add `ImNodes.createContext()`/`destroyContext()` beside them. Forge `forge-core/.../lwjgl2/Lwjgl2ImGuiHost.ensureInitialized()` calls only `ImGui.createContext()` and has NO dispose path (the host lives for the session); it creates no ImPlot context because ImPlot is Fabric-only, so ImNodes will be the first extension the LWJGL2 host ever initializes. Add the create call there; there is nowhere to destroy, which is fine.
- The LWJGL2 spike (do this before any editor code): forge-core depends on `com.github.koxx12-dev:ImGui-Java-Lwjgl2:1.0.0` (api) with the binding compileOnly (forge-core/build.gradle). The shim's natives were built against 1.86.11, whose native surface is a strict subset of 1.86.12 (only ImGuiKnobs was added), so ImNodes natives are expected to be present, but whether the koxx12 rebuild compiled the imnodes extension into its native binary is UNVERIFIED. The spike is a throwaway call path (ImNodes.createContext + beginNodeEditor + one beginNode inside the overlay) run via the 1.8.9 runClient; an UnsatisfiedLinkError there means the shim needs a rebuild or M3 ships Fabric-first. Fabric uses the official spair natives 1.86.12, which compile in all extensions, so only LWJGL2 is at risk.
- What M2 left ready:
  - Entry point: the disabled "Open editor" button in AngleSolverWindow.renderPresetSection; the window already holds the graphStore.
  - Load/save: GraphPresetIO.parse/materialize/fromGraph/toJson. GraphNode.x/y persist, so canvas layout survives round trips. The Node.label field is written from NodeType.label and ignored on materialize; the editor can adopt it for user-editable labels with no format bump.
  - Palette and inspector need no new surface: NodeCatalog.all(); NodeType exposes label, category, requires, branches (Branch carries the Guarantee and its feasibility class for pin typing), params (ParamSpec kind INT/DOUBLE/BOOL/ENUM/STRING with min/max/def/choices), entryMarker/emitMarker, budgetParam, fallbackBranch.
  - Live validation: GraphValidator.validate returns ValidationIssue(severity, nodeId, edgeIndex, message). materialize rejects ERROR graphs, and store.write is a raw string write, so the editor CAN save a preset the picker will then refuse to select; surface ERRORs in-canvas and warn before writing one.
  - Save-and-activate: reuse the picker's flow (writePreset -> refreshPresets -> selectPreset) so an edited graph becomes the live customGraph; do not invent a second adoption path.
- Theme: every editor color goes through ThemeManager accessors, mapped into ImNodes.pushColorStyle; tableStyleCheck runs on :core:build (known false positive on SolverWidgets only).

## 6d. M3 as shipped (2026-07-12), imnodes editor

Spike result, and a correction to 6c's risk assessment: the koxx12 shim ships NO natives at all; its jar is five Java glue classes (LWJGL2 input + a GL3-compat renderer). Each Forge loader shades the official spair natives 1.86.12 (loader build.gradle, `imgui-java-natives-*`), the same binaries Fabric uses, and that dll exports all 77 `Java_imgui_extension_imnodes_ImNodes_*` symbols (verified in the cached `imgui-java64.dll`). The runtime spike confirmed it: a throwaway ImNodes.createContext + beginNodeEditor + one-node frame rendered 10 frames through the 1.8.9 shim (234 vtx) and 10 frames on Fabric (246 vtx), no UnsatisfiedLinkError. There was never a shim-rebuild scenario; the "built against 1.86.11" caveat only constrains the shim's Java-side calls into the binding, not the natives.

Context wiring, per 6c: Fabric `ImGuiImpl.create()` calls `ImNodes.createContext()` beside the ImPlot context and `dispose()` calls `ImNodes.destroyContext()` before the other two teardowns; `Lwjgl2ImGuiHost.ensureInitialized()` calls it right after `ImGui.createContext()`, no dispose path (the host lives for the session). Covers both Forge loaders.

The editor is `core/ui/anglesolver/GraphEditorWindow`, registered as a normal overlay in Application.setupUi and opened from the preset section's now-enabled "Open editor" button.

- Open semantics (the built-in question): everything opens EDITABLE. A selected user preset opens under its name; Save overwrites it. Legacy budget (and any graph not resolved from the store, including a dangling preset name) opens as an unsaved draft: no Save button, only Save As under a new name, i.e. the duplicate flavor rather than read-only. The draft is a deep copy (GraphNode + ParamValues.copy; GraphEdge instances shared, they are immutable), so the live customGraph is untouched until a save round-trips through the store.
- Save reuses the picker's flow exactly: the editor delegates to AngleSolverWindow.writePreset (now package-private) via a SaveHandler wired in the AngleSolverWindow constructor, so write -> refreshPresets -> selectPreset stays the single adoption path and the saved preset becomes the live customGraph.
- Session-local int ids (format untouched): node ints from a counter starting at 1; pin id space is nodeInt*32 with input pin +0, output pins +1..+15 by branch index, static param attributes +16..+31; link ints from an identity-keyed map with its own counter. String node ids remain the only identity in the file.
- Canvas: nodes from the working copy with title bar colored by NodeCategory (ThemeManager tint accessors), node id shown dim next to the type label; input pin on every non-Entry node (CircleFilled + ok color when requires FEASIBLE, Circle otherwise); one output pin per Branch (shape/color by feasibility class: FEASIBLE filled ok, PRESERVES circle accent, UNKNOWN triangle warning); param widgets per ParamSpec kind (inputInt, inputDouble, checkbox, combo, inputText) inside static attributes, all writes through ParamValues.set so spec clamps hold live.
- Live validation: GraphValidator re-runs on every mutation. ERROR nodes get danger title bar + outline, ERROR edges render as danger links, and an issue strip under the toolbar lists everything (clicking an issue pans to the node). Saving a graph with ERRORs opens a confirm modal warning that the picker will refuse to select it.
- Edge editing: dragging pin to pin creates the edge and silently replaces an existing edge on that (node, branch), since at most one edge per branch is legal. Deleting is selection-based via the "Delete selected" toolbar button; Entry/Emit nodes are excluded from deletion and from the add palette. Right-click on the canvas (or the Add node button) opens the palette grouped by category.
- Layout: GraphNode.x/y round-trip through the preset file as before; positions read back from the canvas each frame. When every stored position is zero (all M2-era presets, all built-ins), a longest-path-from-Entry layered auto-layout runs on open; also exposed as a toolbar button.
- Zoom (added post-M3 on user request): imnodes has NO native zoom, so it is emulated. Mouse wheel over the canvas (window scroll is disabled anyway) multiplies a session-local zoom in [0.4, 1.6]; a toolbar percent button resets to 100 centered on the canvas. Per frame the editor pushes the 12 size-ish ImNodesStyleVar entries scaled from a baseline captured once from ImNodes.getStyle(), scales the default and bold fonts via ImFont.setScale + pushFont (NOT ImGui.setWindowFontScale: the 1.86.12 binding generated it as a non-static method, uncallable; and a bare setScale without a pushFont does nothing because FontBaseSize is only rebaked on SetCurrentFont), and multiplies node grid positions by zoom on placement, dividing on readback so GraphNode.x/y stay unzoomed in the model and the preset file. The pan is adjusted on zoom change so the point under the mouse stays fixed (panning += grid * (1 - ratio)). Zoom is view state: never dirties, never saves. Panning: imnodes' native middle-mouse drag still works; right-mouse drag pans too (manual editorResetPanning += mouse delta), and the add-node popup moved from right-click-press to right-click released within a 4 px drag threshold so the two do not fight. The binding exposes no ImNodesIO, so the alt+LMB three-button emulation cannot be enabled. The nodeditor extension (ax::NodeEditor, also in the jar with all 168 natives present) has real canvas zoom, but switching would rewrite the whole canvas layer against the recorded imnodes decision; revisit only if the emulation proves insufficient in-game.

Deviations from the obvious design, and why:

- No keyboard Delete: core is loader-agnostic and the LWJGL2 and GLFW backends use different keycode spaces, so there is no portable key constant; the toolbar button covers it.
- No link drag-detach: binding 1.86.12 exposes pushAttributeFlag but NOT popAttributeFlag, so the EnableLinkDetachWithDragClick flag cannot be pushed without corrupting the imnodes attribute-flag stack. isLinkDestroyed never fires without it; link deletion is selection-based instead.
- No minimap: its 12 color slots would render with unthemed imnodes defaults, and everything else goes through ThemeManager accessors.
- Node.label user labels NOT adopted (6c allowed it): the canvas shows the type label plus the node id, which stays the identity that validator messages reference. Revisit if graphs grow past what ids can disambiguate.

Verification: an editor smoke pass (temporary hook rendering a BuiltinGraphs.fast() draft through the real window for 20 frames on the 1.8.9 shim, 9816 vtx, no assertion or stack imbalance) plus the :core:build gate. Interactive in-game verify (drag, link, save, reload) is pending alongside M2's.

## 6e. Canvas ported to imgui-node-editor (2026-07-13)

The revisit clause in 6d fired: the zoom/pan emulation was judged not worth carrying forward, and the canvas layer of `GraphEditorWindow` was rewritten against the nodeditor extension (ax::NodeEditor, `imgui.extension.nodeditor`, natives already shipped in the pinned 1.86.12 jar on all three loaders). Everything outside the canvas (open/save semantics, SaveHandler, validation strip, int id scheme, preset format, GraphNode.x/y round-trip) is unchanged. What moved:

- Context lifecycle now lives in core: `GraphEditorWindow.open()` destroys and recreates a `NodeEditorContext` (fresh view + selection per session; `setSettingsFile(null)` disables the editor's own state file, verified null-safe in the 1.86.12 JNI glue) and `render()` calls `setCurrentEditor` each frame. The ImNodes context bootstraps in `ImGuiImpl` and `Lwjgl2ImGuiHost` are gone; loaders no longer touch any node editor API.
- Zoom and pan are native. The 12-style-var scale hack, font rescaling, and grid-position multiply/divide dance are deleted; positions apply and read back 1:1 (canvas units equal the old unzoomed grid units, so stored presets are untouched). The toolbar percent button now fits the graph (`navigateToContent`) instead of resetting to 100; the percent readout is measured from `toCanvasX` deltas after `end()` rather than `getCurrentZoom`, whose scale orientation is undocumented. Right-drag pans natively; the add palette hangs off `showBackgroundContextMenu` (right-click without drag), so the manual 4 px drag-threshold disambiguation is gone too.
- Popups cannot open inside the canvas transform, so the add palette and the new enum popup render inside a `suspend()`/`resume()` block, and their `openPopup` calls happen there as well (the canvas child owns a different ID stack than the window, so the toolbar Add button just sets a flag). ENUM params render as a button that opens that suspended popup; combo widgets do not survive inside the canvas. Placement uses canvas-space mouse coordinates captured inside the canvas (toolbar adds land 60 px inside the view's top-left corner).
- Node title bars are drawn by hand: nodeditor has no title bar concept, so the category/danger fill is an `addRectFilled` with top rounding through `getNodeBackgroundDrawList`, using the header row's item rect for the split line. Pin icons (circle, filled circle, triangle by feasibility class) are drawn via the window draw list with `pinPivotRect` pinned to the icon center; output rows right-align against the previous frame's node width.
- Link create/delete use the editor-native interactions: `beginCreate`/`queryNewLink` with live `rejectNewItem` feedback on invalid pin pairs (replace-existing-edge-per-branch logic unchanged), and `beginDelete`/`queryDeleted*` with `rejectDeletedItem` for Entry/Emit. The keyboard Delete deviation in 6d is voided: the editor handles the key through ImGui's key map, portable across both backends. Error links get the danger color per link via the `link()` color overload.
- Issue-click navigation selects the node and `navigateToSelection` pans to it, replacing `editorMoveToNode`.
- Lost relative to imnodes and accepted: the (unused) minimap. Gained and not yet used: `group()` comment boxes and `flow()` link animation, the natural hook for M4's active-path visualization.

## 6f. M4 as shipped (2026-07-13), live run visualization

Data side, all in core with no loader changes anywhere in M4:

- GraphRunState's label-only breadcrumb became a list of Step {nodeId, label, taken}; begin appends a step, end stamps the taken branch on it, so the UI can map every traversal to a concrete edge. NodeStatus gained an evals counter: GraphContext snapshots cmaesEvals + smoothingEvals at beginNode and records the delta at endNode, which covers any node that routes work through those counters without per-node plumbing.
- AngleSolverEngine keeps the run state after the run: lastRunState is set when runJob builds the GraphContext and graphRunState() returns the in-flight state or, once the walk ends, the last one, so the canvas shows the finished walk until the next solve replaces it. isGraphSolving() distinguishes a live graph walk from block solves (which never touch lastRunState). liveProgress() exposes the existing SolveProgress for sampling.
- liveTrajectory() is the world-overlay feed: per SolveProgress version bump it re-runs model.forward over job.spec.asScenario() with the live best yaws (the same recompute liveBestResult already does) and wraps posX/posZ plus the feasibility flag in an immutable LiveTrajectory stamped with a global sequence number. Start-box mutations made mid-run by momentum or translated-start wrappers are not reflected; that is the same staleness the live result panel already has, and the reason Emit never reconciles (section 4).

Editor side (GraphEditorWindow):

- The window polls graphRunState() every frame, before the open check, so sparkline samples accumulate even while the window is closed. Snapshots (steps + statuses) refresh only on run-state version change; adopting a different run instance resets everything. Mapping is by node id: running a graph other than the one on the canvas lights up only the ids the two share, which is exact for the common case (the selected preset is the graph that runs) and harmlessly approximate otherwise.
- Active node: ok-colored border, header badge with live elapsed (and /budget when the node has one), and a bottom progress bar (fraction of budget, or an indeterminate sweep when budgetless). Finished nodes keep a badge with the taken branch (plus xN for revisits) colored by the branch's feasibility class. Badges draw through getNodeBackgroundDrawList and skip themselves when wider than 55% of the node, so node layout never shifts.
- Taken edges animate with the nodeditor flow() hook 6e reserved for this. New steps flow as they complete; adopting a run that is already underway (or finished) skips the catch-up so opening the editor mid-solve does not replay the whole history at once.
- Run panel between the issue strip and the canvas: spinner + elapsed while solving ("Last run" afterwards), right-aligned live objective and violation (violation ok-colored once the best is feasible), a horizontally scrolling breadcrumb of step labels (click pans to the node; tooltip shows node id, taken branch, last visit time, visits, evals; auto-scrolls right while running), and objective/violation step-line sparklines drawn with the window draw list (ImPlot is Fabric-only, so core cannot use it), x-axis is solve time, sampled once per SolveProgress version.

World overlay (live best path):

- LiveBestPathSource implements ConstraintBoxSource: one small marker box per tick at the live best's predicted X/Z, anchored at the recorded path's foot Y for that tick (ExactJumpModel's posY is not physical between jumps, and Y is input-determined, so the recorded height is the honest anchor). satisfied = live feasibility, so the trail outlines green/red through the existing palette with no new colors.
- PathRenderPlan gained a second static source (setLiveSource) emitted into the same trailing constraint region the loaders already draw; counts sum both sources and the structural hash mixes both revisions, so the loaders needed no changes at all. The live region is gated by the solver view being open (same ActiveGate as plates), NOT by showConstraints. Trajectory adoption is throttled to 150 ms so an improvement burst does not rebake the world buffers every frame.
- ConstraintPlate gained a pickable flag (default true, existing constructor unchanged); BoxController's pickWorld and isCursorOverConstraint skip non-pickable plates, so the moving trail never intercepts clicks or suppresses attacks.

## 6g. M5 as shipped (2026-07-13), constant promotion

One solver class per commit, fifteen commits, each gated by a green :core:test run. Every promoted class follows the WrapWindowIls.Config precedent: a nested `public static final class Config` with public mutable fields whose initializers ARE the old constants (so `new Config()` is the default, byte-identical), a Config-taking overload on each entry point, and the pre-existing signatures delegating with a fresh default Config. The node that wraps each component builds the Config from its ParamValues, so every knob is a clamped node param and a preset-file field from now on. Param keys are serialization contract per 6b; everything added here is additive, so M2-era presets load unchanged.
