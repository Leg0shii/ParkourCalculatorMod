## 2. Architecture as built (core/.../anglesolver/coldsearch/)

Pipeline: ArcSweep (enumeration) -> quickScoreSig screen -> probeSig -> certify -> FreeStartSolve.violationAt == 0.0 byte-exact.

- `ColdProblem`: permitted inputs only (constraints, slip overrides, press ticks = last ground tick per run, t0 rect, DF corridors as momentum walls, tail walls).
- `KeyLine` / `LineSpec`: combo alphabet (NONE/W/WA/WD/A/D/S/SA/SD), sprint machine, sig format `<combo><. or +>` per tick, spec building.
- `ArcSweep`: facing carried symbolically as linear forms A*sin(theta)+B*cos(theta) per velocity/displacement component; start rect eliminated pairwise into facing arcs (`leqZero` single-segment form); inertia gate handled by case-splitting states on straddle; walls cut arcs with margin rectSlack+2e-3; reachability funnel (`funnelOk`, scalar `reachable` ported to arc velocity ranges via `evalRange`); tail-wall margin filter at emission; per-sig arc UNION across gate branches surviving collector eviction (`emittedBySig` holds the canonical candidate, re-accepted after eviction). Modes: exhaustive DFS for level <= cfg.arcExhaustiveMaxLevel (4), changes-first order, no stages; staged beams above (rank ties make those a lottery, see lessons); `runSeeded` (grammar zone forcing).
- `StratPrefixes`: press-anchored grammar seeds (pessi k x coast{NONE,S,A,D,SA,SD} x engage{W,WA,WD}, fmm k, mark side k, run+jam), k bounded by gap to next press.
- `ColdSearch`: Config (arcNodeCap 300M, arcExhaustiveMaxLevel 4, seededPass/seededPreCapMax/seededSuffixCap, certifyCap 400, rectSlack 0.05, timeBudgetMs); solve() = seeded pass ladder then blind level ladder, both through shared `probeCertify(tag, quickKeep, certifyCap, skipIfAllInf)`; `quickScoreSig` = probeAt at 2 degree steps over merged arcs + one refine of the best finite hit; probe-monotonicity invariant (probeSig starts from the screened score/theta, may only improve); `certifyLine` = the regression primitive (0.4 s per pin).
- Test screens (all env-gated, same package): ColdSearchScreen (PKC_COLD_FILE/BUDGET_MS/LOG), ColdWarmCheckScreen (warm oracle: human rows -> sig -> certifyLine; THE first thing to run on any capture), ColdSweepCheckScreen (emission gate incl. ARC block + dbg prefix tracking), ColdScreenRankScreen (PKC_COLD_RANK_FILE/SIG/LEVEL: sweeps, then ranks a target sig under the real screen, prints the target's full theta profile; the cheap iteration loop), ColdArcDebugScreen (arc-vs-scalar equivalence on a theta grid; scalarOnly MUST be 0), CaptureSanityScreen, ColdCertifyLineScreen.

## 3. What we learned (invariants, earned the hard way)

1. Estimate SELECTION, not evaluation. "Dual solves a line in 0.05 ms" says nothing about finding which of 10^15 lines to evaluate. This mis-estimate caused the "easy" promise.
2. Warm-oracle EVERY capture before optimizing anything. certifyLine on the human line splits enumeration-blocked (j716, j1150) from certify-blocked (j154) in 2 minutes per capture.
3. Constraint-free run-up ticks give ranking NO signal. Every heuristic beam/sink rank (velocity, width, arc length, funnels) leaves millions of ties; retaining one specific needle through 7 sequential culling points is a lottery. Proven by dbg prefix tracking (dbgReached/dbgKept per stage). Fixes that worked: exhaustive enumeration at low levels; grammar prior for high levels (user-ruled REQUIRED and general).
4. Rect WIDTH is ANTI-correlated with certifiability on facing-tied captures. Width peaked at theta 12.5 where probe was Infinite; the certifiable basin (probe 7.3e-5 at 21.0) had width -0.015. Width killed three screen designs and one certify window ranking. Never rank by width; rank by probeAt (recoverStart violation), which is finite exactly in certifiable basins (3.5 degree wide swaths, 2 degree grid suffices).
5. Downstream stages must never degrade upstream measurements (monotonicity). probeSig's width-refined sampling DEGRADED screened candidates below the certify cut; fixed by initializing from the screen's (score, theta).
6. Per-sig arc fragments lie. The same sig emits from many gate branches with different arcs; keep the UNION on one canonical candidate that survives collector eviction, or screens look in the wrong facing window.
7. Fast targeted gates beat solve-loop debugging. The rank screen (14 min) replaced 30-45 min blind solves; the theta-profile dump chose the working screen from DATA after three theory-driven failures.
8. Process: verify detached launches actually started (two silent gradlew path failures cost 50 min: cmd needs the FULL path to gradlew.bat, current directory is not searched); the PowerShell tool kills backgrounded commands at 10 min (use Start-Process with a cmd script + done-marker + Monitor tails); PKC_* env changes need --rerun; test stdout lands in TEST-*.xml only at JVM exit; state full-loop costs, not next-step ETAs.

## 9. The lattice-search direction (session 3, user-driven; the strategic reframe)

The knife-edge captures are CALCULATED optima on a discrete lattice, not stumbled-upon feasible points. Two structural facts make this the right frame and make it tractable:
1. With a fixed facing (no turn), the whole momentum is LINEAR in (sin theta, cos theta) and the start (sx, sz); the only nonconvexity is the single facing angle plus the free air yaws. So per key-pattern it is a small global optimisation (the momentum-milp-handoff premise), not a search to brute-force.
2. The yaw is quantised to 65536 sine-LUT buckets over 2*pi (0.005493 deg each). The byte-exact solution is a lattice point; near a binding constraint the feasible set can be one bucket wide (proven for j154's facing). Rounding a continuous optimum lands on a neighbour and misses.

The certify win above is the first, narrow instance (bucket-sweep the ONE nonconvex facing angle). The full programme, still to build, matches the community tools (TAS-Wolfram, Sheepram) and this repo's own reference notes (reference_global_optimization_mc, reference_byte_exact_certified_solver):
- LP / convex relaxation of each angle's arc (the levers-doc 24-gon outer approx; pieces in ClosedFormSolve / CostateDualSolver) for a certified bound and the active-constraint set.
- Branch-and-bound / discrete local search along the binding seam over the LUT buckets (the missing "DLS over the sine-bucket lattice"), verified byte-exact through ExactJumpModel.
- This also OPTIMISES rather than just certifies, so it can beat the human line (more margin, lower objective, or fewer input changes). That is the VISION.md endgame.
Next concrete step beyond j154's facing bucket-sweep: extend the bucket search to the air yaws when the slice solver's snapped continuous yaws miss the seam (j154's air happened to certify from the slice solver once the facing bucket was right; a tighter capture may need the air lattice too).
